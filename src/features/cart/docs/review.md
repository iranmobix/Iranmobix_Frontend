# گزارش بازبینی و اعتبارسنجی Cart

بررسی اولیه: ۲۰۲۶-۰۹-۲۴؛ تکمیل و بازبینی نهایی: ۲۰۲۶-۰۹-۲۶. مبنا: برنچ feature/cart پس از 8ecf2c8، راهنمای مشترک در worktree .project-docs و کد فعلی وابسته به Auth/Product.

## تغییرات این مرحله

- مدل واقعی cart در cart.types.ts و مدل طراحی در cart-preview.types.ts قرار گرفت؛ importها هماهنگ شدند.
- انتخاب موک از CartPage به useCart و adapter خواندن منتقل شد؛ دادهٔ نمونه حالا همان schema/mapper را طی می‌کند و query key مستقل دارد.
- schemaهای پاسخ و payload با satisfies به type قرارداد مربوط متصل شدند.
- منطق mount/navigation انتقال بعد از ورود به use-cart-merge-flow رفت. تعریف مسائل انتقال بین UI و service مشترک شد.
- query/mutation keyها متمرکز شدند.
- خطای اعتبارسنجی دادهٔ نمونه هم در صفحه نمایش داده می‌شود و راه تلاش دوباره/بازگشت به API دارد.
- مصرف Auth و Product از ورودی عمومی cart انجام می‌شود. در این دو فیچر فقط import مصرف‌کننده تغییر کرد.
- route پرداخت نازک شد؛ ترکیب fixture و بنر به CheckoutPreviewPage منتقل شد.
- دو فایل خالی بدون مصرف cart-link.tsx و cart.store.ts حذف شدند.
- مستندات با فهرست هر فایل، مرز واقعی/موک، API و راهنمای توسعه بازنویسی شدند.

پنج تست افزوده‌شده به طور مشخص موک بدون HTTP/session، clone مستقل، اعتبارسنجی موک، باقی ماندن خطای شبکه/قرارداد، انتقال signal لغو درخواست و جدایی cache واقعی/نمونه را پوشش می‌دهند.

تست‌های قبلی، مبلغ دقیق، ورودی نامعتبر، reuse/انقضای session، storage مسدود، timeout افزودن، header/payload، merge کامل/ناقص/ناموفق و reducer/تخفیف/پرداخت پیش‌نمایش را پوشش می‌دهند. این‌ها اثبات موفقیت درخواست روی سرور واقعی نیستند.

خطاهای TypeScript باقی‌مانده در Blog، AuthButton، service/hookهای Product، SalesExpertCard و Search هستند. اصلاح آن‌ها بخشی از این ریفکتور نبوده است. build کامل سبز یا رفتار مرورگر با این نتیجه ادعا نمی‌شود.

## محدودیت‌های مهم تحویل

1. پاسخ داخلی product/pricing/availability و چند object دیگر هنوز قرارداد دقیق ندارد؛ مقدار UI از آن حدس زده نشده است.
2. Auth همین برنچ قدیمی‌تر از feature/auth است؛ تأیید cookie/Bearer و اتصال نسخهٔ جدید لازم است.
3. پاک‌سازی cache روی ورود داریم؛ قرارداد logout/account switch و همگام‌سازی چند تب کامل نیست.
4. /cart/checkout همچنان پیش‌نمایش محلی است؛ به سبد واقعی، سفارش یا پرداخت متصل نشده است.
5. deep import کامپوننت‌ها و مدل محصول تا ایجاد public export مناسب در Product باقی است.

روش تکرار بررسی‌ها در [README](README.md) و مسیر توسعهٔ بعدی در [decisions.md](decisions.md) آمده است.

## پیگیری خطای sku_attributes در افزودن

فرم خرید ویژگی‌های price.attributes را دریافت می‌کرد ولی ارسال نمی‌کرد. اکنون ProductSkuAttributes کنترل انتخاب را نمایش می‌دهد و resolveProductSkuSelection مقادیر مجاز را با نام دقیق ویژگی آماده می‌کند. ویژگی تک‌گزینه‌ای انتخاب می‌شود؛ ویژگی چندگزینه‌ای تا انتخاب کاربر دکمه را غیرفعال نگه می‌دارد. شناسه‌های color/guarantee مستقل از این object هستند. شکل نام → مقدار برای sku_attributes از مدل فعلی دیتیل استنباط شده و تأیید درخواست موفق بک هنوز لازم است.

پس از این اصلاح: ۲۰ تست cart-api و ۱۸ تست پیش‌نمایش، در مجموع ۳۸ تست پاس شدند؛ lint چهار فایل مربوط بدون خطا/هشدار و TypeScript با همان ۱۶ خطای پیشین و صفر خطا در فایل‌های مرتبط است. SSR فرم نیز با جایگزینی دکمهٔ افزودن و SVG بررسی شد: انتخاب ناقص غیرفعال، تک‌گزینه‌ها در payload و محصول بدون ویژگی با quantity تنها. درخواست واقعی به بک در این بررسی ارسال نشده است.

این پیگیری علاوه بر import قبلی، منطق فرم Product را تغییر داده است. فایل‌های اضافه‌شده:

- [کنترل انتخاب SKU](../../product/components/detail/product-sku-attributes.tsx)
- [اعتبارسنجی انتخاب SKU](../../product/utils/product-sku-selection.ts)

## هماهنگی ظاهر فرم خرید با طرح ـ ۲۰۲۶-۰۹-۲۷

کارت اطلاعات ارتفاع طبیعی و فاصله/تایپوگرافی جمع‌وجور دارد؛ قیمت‌های پلکانی متناسب با عرض کارت چیده می‌شوند. گارانتی تمام‌عرض و تعداد/رنگ در یک ردیف هستند. اگر محصول رنگ مستقل شناسه‌دار نداشته باشد، ویژگی SKU با نام color/colour/رنگ در همان جای رنگ نمایش داده می‌شود. سایر ویژگی‌های لازم برای payload زیر این ردیف باقی می‌مانند. ترجمهٔ label رنگ، نام کلید API را عوض نمی‌کند. اگر بک هم رنگ شناسه‌دار و هم رنگ SKU بدهد، این دو قرارداد مستقل حفظ می‌شوند و خودکار به یکدیگر نگاشت نمی‌شوند.

انتخاب‌ها همچنان از فرم مشترک اصلی و خلاصهٔ خرید ارسال می‌شوند. ترتیب نمایش و عدم تکرار کنترل رنگ برای محصول SKU، مسدود شدن انتخاب ناقص و payload کامل نمونهٔ دوربین با SSR بررسی شدند؛ state، دکمهٔ افزودن و SVG در تست جایگزین شدند. جمع تست‌ها اکنون ۳۹ پاس است، lint بدون خطا/هشدار و TypeScript همان ۱۶ diagnostic قبلی با صفر خطا در فایل‌های مرتبط دارد. مرورگر پروژهٔ فعالی در دسترس نبود؛ تطبیق تصویری مرورگر و پاسخ بک زنده تأیید نشده‌اند.

## اصلاح نهایی طبق درخواست کاربر: فقط سه کنترل

فرم خرید فقط گارانتی، تعداد و رنگ را نمایش می‌دهد. همهٔ ویژگی‌های غیررنگ SKU با اولین مقدار معتبر در ترتیب پاسخ بک ارسال می‌شوند؛ انتخاب قدیمی آن‌ها در state نیز نادیده گرفته می‌شود. رنگ مقدار انتخاب‌شدهٔ معتبر کاربر را حفظ می‌کند و در نبود انتخاب معتبر، اولین گزینهٔ بک پیش‌فرض است. نبود مقدار معتبر برای یک ویژگی الزامی همچنان ارسال را متوقف می‌کند.

این تصمیم جایگزین نمایش و الزام انتخاب دستی مدل/رزولوشن در مراحل قبلی است. برای fixture دوربین، model number برابر HDV-206KM و image resolution (video) برابر 4 K در payload هستند و کنترلی در فرم ندارند. ۳۹ تست پاس شدند؛ رندر SSR با دکمه و SVG جایگزین‌شده نیز سه کنترل، حضور پیش‌فرض‌ها در payload و فعال بودن افزودن با دادهٔ کامل را تأیید کرد.

## اتصال نهایی نمایش سبد به پاسخ واقعی

تایپ و schema بخش‌های product، selected_options، pricing، availability و owner بر اساس پاسخ واقعی پنج‌ردیفی تکمیل شدند؛ related_products نیز نگهداری می‌شود. mapper حالا snapshot محصول، رنگ SKU و قیمت‌های ردیف را به domain مشخص تبدیل می‌کند. productData خام قبلی حذف شد.

CartItem از همان UI و ProductCardMedia مشترک برای سبد واقعی و پیش‌نمایش استفاده می‌کند. نام/لینک/تصویر، رنگ هر ردیف و سایر ویژگی‌های ثبت‌شده نمایش داده می‌شوند. مبلغ ردیف از final_total_price با currency سبد است و با قیمت ارزی product اشتباه نمی‌شود. برای رنگ hex حدسی تولید نمی‌شود. seller=null و گارانتی بدون label نمایش ندارند؛ شکل غیر null بعضی فیلدها هنوز نمونه می‌خواهد.

نتیجهٔ نهایی این مرحله: ۲۵ تست cart-api و ۱۸ تست پیش‌نمایش، در مجموع ۴۳ تست پاس. تست رندر از پاسخ واقعی استفاده می‌کند؛ Next Image و assetهای SVG جایگزین شده‌اند. بررسی حالت دو رنگ یک محصول، مقدار دقیق مبلغ بزرگ، تعداد چندتایی بدون بازحساب جمع، null تصویر/موجودی و پاسخ nested نامعتبر نیز پاس شد. ESLint فیچر cart و دو فایل مرتبط Product بدون خطا/هشدار است؛ TypeScript فقط همان ۱۶ خطای قبلی خارج از فایل‌های تغییرکرده را گزارش می‌کند.

این مرحله بخش «nested product/pricing/availability نامشخص است» در گزارش اولیه را جایگزین می‌کند. مرورگر تعاملی و درخواست زندهٔ بک اجرا نشده‌اند؛ مبنا پاسخ واقعی ارسالی کاربر و تست‌های محلی است.

## تطبیق طرح و مشخص کردن کمبودهای بک

ردیف‌ها فشرده‌تر شدند؛ تصویر ۱۱۰ پیکسلی، اطلاعات سمت راست، قیمت و کنترل تعداد سمت چپ؛ خلاصه با سود خرید و ثبت اولیه به طرح نزدیک شد. پیام‌های کمبود کنار همان فیلد دیده می‌شوند. هیچ درصد، قیمت اصلی، رنگ CSS یا فروشندهٔ نمونه به پاسخ واقعی اضافه نشده است. جزئیات SKU خارج از طرح در domain حفظ شده‌اند.

۴۶ تست شامل رندر وضعیت‌های مفقود/نامشخص، کنترل‌های غیرفعال، سود صفر و عدم ترکیب ارز قیمت محصول و ردیف پاس شدند. lint فیچر بدون خطا و هشدار است. بررسی مرورگری و اتصال زنده به بک انجام نشده است.

## بازبینی مطابق راهنمای مشترک — ۲۰۲۶-۰۹-۲۸

مرجع: `.project-docs/docs/README.md` و `feature-development.md`؛ سند `frontend-architecture.md` برای توضیح لایه‌ها نیز خوانده شد. پوشه‌ها و فایل‌های api، types، schema، mapper، service، hook، component، mock، utility، constants و export عمومی با راهنما تطبیق داده شدند.

اصلاحات این مرحله:

- guard و وضعیت مشترک افزودن از AddToCartButton به useAddToCart منتقل شد؛ کامپوننت callback/وضعیت هوک را مصرف می‌کند و Query را مدیریت نمی‌کند.
- mapGuestCartSession در مپر موجود اضافه شد؛ زمان شروع از سرویس ورودی است تا mapper خالص بماند.
- schemaهای PATCH/DELETE نیز با satisfies به type ورودی متصل شدند.
- فرمت و اعتبار مبلغ ریالی به cart.utils منتقل شد؛ کامپوننت پرداخت دیگر برای formatter به service وابسته نیست.
- فرم آدرس از React Hook Form و checkoutAddressSchema استفاده می‌کند؛ خطای فیلد قابل مشاهده و قابل دسترسی است. همان schema در هوک قبل از ثبت آدرس استفاده می‌شود.
- متن‌های متناقض دربارهٔ نبود API تغییر/حذف، تعداد endpointها، گارانتی، نمایش ویژگی‌های SKU و مسئولیت فایل‌ها اصلاح شدند. این بخش وضعیت فعلی است؛ گزارش‌های بالاتر سابقهٔ مراحل قبلی‌اند.

اعتبارسنجی: ۵۳ تست پاس شد؛ بررسی TypeScript فقط همان ۱۶ خطای قبلی بیرون Cart را گزارش داد. بررسی وابستگی‌ها هیچ import سرویس/React Query یا استفادهٔ storage در کامپوننت‌های Cart نشان نداد. `git diff --check` پاس شد. تست مرورگری و بک زنده انجام نشده است.

محدودیت باقی‌ماندهٔ یکپارچه‌سازی: cache مالک حساب/خروج هنوز به قرارداد Auth جدید وابسته است؛ تصمیم و وضعیت دقیق در decisions.md ثبت شده است. endpoint ثبت سفارش و پرداخت نیز ارائه نشده؛ مسیر checkout همچنان پیش‌نمایش صریح است.
