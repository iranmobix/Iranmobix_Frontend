# تصمیم‌های معماری و وضعیت آن‌ها

این سند «آنچه هست» را از «روش پیشنهادی ادامهٔ توسعه» جدا می‌کند. پیاده‌سازی فعلی به‌تنهایی تصمیم امنیتی یا تأیید نهایی قرارداد بک محسوب نمی‌شود.

| موضوع | وضعیت فعلی | قاعدهٔ ادامهٔ توسعه |
| --- | --- | --- |
| جداسازی HTTP | authApi از httpPost مشترک استفاده می‌کند | URL و transport در api بماند؛ component کلاینت جدید نسازد |
| سرویس | verify پاسخ را مپ می‌کند؛ دو عملیات دیگر عبوری‌اند | use case در service؛ لایهٔ عبوری فقط برای مرز مصرف ثابت نگه داشته شود، لایهٔ بی‌دلیل اضافه نشود |
| مپر | تبدیل نام‌ها جدا شده ولی user_type جا افتاده | تمام فیلدهای اجباری خروجی را صریح مپ کنید؛ null واقعی را حفظ کنید |
| validation | schema ورودی فرم وجود دارد؛ schema پاسخ شبکه ندارد | type و runtime validation را یکی ندانید؛ برای دادهٔ خارجی نامطمئن در مرز ورود validation تعریف کنید |
| state | state فرم محلی، request state در Query، flow state در useOtpFlow | state را با مالک مشخص نگه دارید؛ آن را هم‌زمان در چند store کپی نکنید |
| توکن | access و refresh در localStorage نوشته می‌شوند | تصمیم storage نیازمند توافق مستقل با بک است؛ ادعای HttpOnly-only مستند قدیمی حذف شده است |
| UI | چند فایل دارای مسئولیت مشخص و چند wrapper کوچک دارد | اندازهٔ فعلی فایل‌ها قانون تکثیر در فیچرهای جدید نیست |
| استفادهٔ مجدد | HTTP، provider و UI مشترک موجودند | اشتراک بر اساس مسئولیت مشترک؛ tokenStorage ابزار عمومی همهٔ فیچرها نیست |
| public API | auth/index.ts وجود ندارد | برای فیچر جدید exportهای محدود و واقعی ایجاد کنید؛ export به فایل خالی یا ناموجود ممنوع |
| نام‌گذاری | کامپوننت‌ها kebab-case؛ hookها camelCase | در هر فیچر با قرارداد موجود هماهنگ بمانید؛ تغییر نام موجود در PR مجزا |
| موک | فقط mockSendOtp ناقص در flow است | موک کامل را در adapter/data جدا بنویسید؛ خطای بک خودکار موفقیت موک نشود |

## تصمیم‌های باز

- منبع قطعی وضعیت ورود بعد از reload و قرارداد access/refresh/cookie.
- محل و رفتار refresh، logout و بازیابی current user.
- قرارداد خطاهای API و پیام مناسب رابط.
- استفاده از مدت انتظار برگشتی بک، به جای عدد ثابت ۶۰.
- یکسان‌سازی user_type دامنه و جای VerifyOtpResult؛ اکنون در فایل api.types قرار دارد ولی user آن domain است.
- انتقال ابزار چندمصرف‌کننده به shared تنها بعد از روشن شدن وابستگی‌ها؛ shared نباید مخزن تمام فایل‌های کوچک شود.

این بازبینی فقط متن مستندات را عوض می‌کند؛ تصمیم‌های باز هنوز در کد اجرا نشده‌اند.
